## 🎯 시스템 개요

본 시스템은 회의 음성 파일을 업로드하면 자동으로 다음과 같은 처리를 수행합니다:

1. **STT 변환**: 음성을 텍스트로 변환 (Whisper)
2. **RAG 참고**: 참고폴더의 문서를 참고하여 컨텍스트 확보
3. **AI 분석**: 현대제철 AI 모델을 사용하여 회의 내용 구조화
4. **PPT 생성**: 분석 결과를 바탕으로 회의록 PPT 자동 생성

### 주요 특징

| 기능 | 설명 |
|------|------|
| **RAG (Retrieval-Augmented Generation)** | 참고폴더의 문서를 AI 분석에 자동 반영 |
| **다중 AI 모델 지원** | 4 가지 AI 모델 중 선택하여 분석 가능 |
| **자동 PPT 생성** | 분석 결과로 즉시 사용 가능한 PPT 산출물 생성 |
| **오타 자동 수정** | 130+ 개 오타 사전 + 사용자 등록 기능 |
| **웹 UI** | 브라우저에서 직관적으로 작동 |
| **수정 및 저장** | 분석 결과 수정 후 PPT 생성 가능 |

### 단계별 상세 프로세스

#### 단계 1: 음성 파일 업로드
```
사용자 → 파일 선택 → 업로드 → web_uploads/ 저장 → file_id 발급
```

#### 단계 2: 참고폴더 (RAG)
```
파일 업로드 → 문서 로드 → 텍스트 추출 → 임베딩 → FAISS 벡터 DB 저장
```

#### 단계 3: AI 분석
```
STT 텍스트 + RAG 컨텍스트 → 오타 수정 → 프롬프트 구성 → vLLM API 호출 → JSON 결과
```

#### 단계 4: PPT 생성
```
JSON 데이터 → 슬라이드 생성 → Reports 폴더 저장 → 다운로드 가능
```

## 🔍 RAG 기능

### 개요

본 시스템은 **RAG (Retrieval-Augmented Generation)** 기술을 적용하여 참고폴더의 문서를 AI 분석에 통합합니다.

```
┌─────────────────────────────────────────────────────────────┐
│                   RAG 아키텍처 구조                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ┌──────────────┐                                          │
│  │  Context     │  참고폴더 문서 로드                       │
│  │  Provider    │  (파일 읽기, 텍스트 추출)                 │
│  └──────┬───────┘                                          │
│         │                                                   │
│         ▼                                                   │
│  ┌──────────────┐                                          │
│  │  Embedding   │  문서를 벡터로 변환                       │
│  │  Engine      │  (sentence-transformers)                 │
│  └──────┬───────┘                                          │
│         │                                                   │
│         ▼                                                   │
│  ┌──────────────┐                                          │
│  │  Vector DB   │  FAISS 인덱스 구축                       │
│  │  (FAISS)     │                                          │
│  └──────┬───────┘                                          │
│         │                                                   │
│         ▼                                                   │
│  ┌──────────────┐                                          │
│  │  Retriever   │  쿼리 기반 유사 문서 검색                 │
│  └──────┬───────┘                                          │
│         │                                                   │
│         ▼                                                   │
│  ┌──────────────┐                                          │
│  │  Generator   │  검색 결과를 프롬프트에 포함하여 AI 호출  │
│  │  (AI Model)  │                                          │
│  └──────────────┘                                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### RAG 처리 흐름

```
1. 파일 업로드 (서버 시작 시 자동 또는 수동)
   ↓
2. 문서 로드 (rag_context.py)
   - 텍스트 파일: 직접 읽기
   - PDF/Word/PPT/Excel: 전용 라이브러리로 추출
   ↓
3. 청킹 (Chunking)
   - 1000 문자 단위로 분할, 200 문자 오버랩
   ↓
4. 임베딩 (Embedding)
   - 각 청크를 384 차원 벡터로 변환
   ↓
5. 벡터 저장 (FAISS)
   - 유사도 검색을 위한 인덱스 구축
   ↓
6. 검색 (Retrieval)
   - 회의 내용과 유사한 상위 5 개 청크 검색
   ↓
7. 프롬프트 조립
   - 검색된 내용을 AI 프롬프트에 포함
   ↓
8. 생성 (Generation)
   - AI 가 참고내용을 반영하여 분석
```

### 지원되는 파일 형식

| 파일 형식 | 확장자 | 라이브러리 |
|-----------|--------|-----------|
| 텍스트 | .txt, .md | - |
| JSON | .json | - |
| CSV | .csv | - |
| Word | .docx | python-docx |
| PDF | .pdf | PyMuPDF |
| PowerPoint | .pptx | python-pptx |
| Excel | .xlsx | pandas |

### RAG UI 기능

| 버튼 | 기능 |
|------|------|
| **파일 업로드** | 참고폴더에 문서 업로드 |
| **검색 준비 다시하기** | 인덱스 새로고침 (새 파일 반영) |
| **검색** | 참고파일에서 키워드 검색 |

### RAG API 엔드포인트

## 🔤 오타 자동 수정 기능

### 개요

**STT 변환 후, AI 분석 전에** 자동으로 오타를 수정하여 AI 분석 정확도를 높입니다.

### 구성 요소

```
┌─────────────────────────────────────────────────────────────┐
│                   오타 수정 아키텍처                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  STT 텍스트 → [오타 수정 엔진] → 수정된 텍스트 → AI 분석      │
│                  │                                          │
│                  ▼                                          │
│         ┌──────────────────┐                               │
│         │  corrections.json│  (사용자 등록 사전)             │
│         │  + 기본 사전     │  (130+ 개 항목)                 │
│         └──────────────────┘                               │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 오타 수정 사전

**기본 사전** (130+ 개 항목):
- 부서명: `재강팀` → `재경팀`, `제공팀` → `재경팀`
- 시스템명: `추리 시스템` → `출입시스템`, `출시 시스템` → `출입시스템`
- 용어: `팩이` → `폐기`, `패키지` → `폐기`, `아벤실적` → `입고실적`
- 숫자/날짜: `1 창` → `1 차`, `6 개일` → `6 개월`, `2000 학기` → `2000 건`

**사용자 등록 사전**:
- 웹 UI 에서 직접 등록/삭제 가능
- `corrections.json` 에 영구 저장
- 시스템 재시작 없이 즉시 적용

### 사용 방법

#### 1. 웹 UI 에서 등록
```
5. 오타 수정 관리
┌─────────────────────────────────────────────┐
│ [틀리는 단어] → [올바른 단어]  [등록]       │
│                                             │
│ 등록된 오타 수정 (130)                        │
│ ┌─────────────────────────────────────────┐ │
│ │ 재강팀 → 재경팀            [삭제]        │ │
│ │ 팩이 → 폐기                [삭제]        │ │
│ └─────────────────────────────────────────┘ │
└─────────────────────────────────────────────┘
```

#### 2. 파일 직접 편집
`corrections.json` 파일을 텍스트 에디터로 열어서 추가/수정:
```json
{
  "틀린단어": "올바른단어",
  "예시": "테스트"
}
```

### 오타 수정 API 엔드포인트

| 엔드포인트 | 방법 | 설명 |
|------------|------|------|
| `/api/corrections` | GET | 오타 수정 사전 목록 조회 |
| `/api/corrections` | POST | 오타 수정 항목 추가 |
| `/api/corrections/{word}` | DELETE | 오타 수정 항목 삭제 |

### 동작 원리

```python
# AI 분석 전 자동 적용 (ai_analyzer.py)
corrected_stt = apply_corrections(stt_text)

# 모든 오타 일괄 수정
for wrong, correct in corrections.items():
    text = text.replace(wrong, correct)
```

### 효과

- **자동 적용**: 분석 실행 시 자동으로 모든 오타 수정
- **로그 출력**: 수정된 오타 수 콘솔에 표시
- **지속 학습**: 사용자가 등록한 오타는 영구 저장

AI 분석 결과를 사용자가 직접 수정하고, 수정된 내용으로 PPT 를 생성할 수 있습니다.

### 사용 방법

1. **분석 실행**: AI 분석 완료 후 결과 표시
2. **수정 버튼 클릭**: 분석 결과가 편집 모드로 전환
3. **내용 수정**: 회의 제목, 목적, 참석자, 논의사항, 결정사항, 액션 아이템 수정
4. **저장 버튼 클릭**: 브라우저에 수정 내용 저장
5. **PPT 생성**: 수정된 내용이 반영된 PPT 생성

### 저장 위치

- **브라우저 메모리**: `currentMeetingData` 변수에 임시 저장
- **서버 파일**: PPT 생성 시 `web_uploads/{file_id}_result.json` 에 영구 저장

### API 엔드포인트

| 엔드포인트 | 방법 | 설명 |
|------------|------|------|
| `/api/save-edit` | POST | 분석 결과 수정 저장 |

## 🔌 API 엔드포인트

### 음성/분석 API

| 엔드포인트 | 방법 | 설명 |
|------------|------|------|
| `/api/upload` | POST | 음성 파일 업로드 |
| `/api/analyze` | POST | STT 변환 및 AI 분석 |
| `/api/save-edit` | POST | 분석 결과 수정 저장 |
| `/api/generate` | POST | PPT 생성 |
| `/api/download/{file_id}` | GET | PPT 다운로드 |
| `/api/status/{file_id}` | GET | 처리 상태 확인 |

| 엔드포인트 | 방법 | 설명 |

| `/api/reference/files/{filename}` | DELETE | 참고파일 삭제 |
